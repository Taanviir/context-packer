What 120 held-out commits showed

Jev beat keyword search on three of four repositories. A change I expected to help didn't, and the local model didn't beat keywords. The whole study cost about $2 of Jev tokens.

The setup

A ranking tool is only useful if the files it puts first are the ones the change needs. Git history already records that. So each task is a real commit subject, the answer is the set of source files that commit modified, and the candidates are the repository as it was one commit earlier, filtered exactly as the tool filters a working tree.

Six repositories are pinned to a commit: hono (TypeScript, about 270 source files at the sampled commits), rich (Python, 160), gin (Go, 73), prometheus (Go and TypeScript, 1,220), httpx (Python) and ripgrep (Rust). From each, a fixed hash order picks 10 dev tasks and 30 test tasks among commits that modify one to five existing source files and add or delete none. Anything I tuned, I tuned on dev. The test tasks ran once per variant.

The main result

Pooled over the 120 test tasks from the four Jev repositories:

Jev0.690.780.882.5 s$0.007

The paired difference at ten is +9.1 points, with a 95% bootstrap interval of +3.6 to +15.2. At five it's +13.3 (+7.2 to +19.8). The gain is largest where the list is shortest, which is where an agent's attention is.

By repository, Jev's recall@10 gain was +10.8 points on hono, +11.9 on rich and +14.4 on prometheus. Gin was a tie (−0.8, interval −10.8 to +10.0). Gin has 73 source files and keywords already found 87% of the answers there, which leaves little to gain. The findings page has every interval.

The idea that didn't work

The sketcher that summarizes each file for the wide pass looks for Kotlin keywords: class, fun, val, object. On a Python or Go file, that leaves little besides the path. Per-language rules looked like the obvious improvement, so I wrote them for TypeScript, Python, Go, Rust, C#, Swift and a few more, with docstrings and /// comments.

On dev they tied. On test they tied again: −0.4 points at ten, interval −2.5 to +1.3. And they cost more, because richer sketches are longer: 58% more tokens on prometheus.

The reason is in the pool size. Up to 120 files get a full-source read, and on repositories of 70 to 1,200 files, that pool already holds most of the answers, chosen partly by BM25. The sketch pass only has to add a few files to the pool, and a path plus a file name often does that as well as a list of declarations. So the per-language sketcher didn't ship. It stays in the benchmark folder so the result can be reproduced. Sketches may matter on much larger repositories, but I didn't measure that.

The local model

Laya's benchmark run on gin and httpx is still in progress; this paragraph will carry its numbers.

A faster keyword ranker, same answers

On a 14,004-file checkout of VS Code, a keyword pack took 4.2 seconds and 740 MB, most of it building a term map for every word of every file. BM25 only needs counts for the query's own terms and each file's length. Counting just those brought ranking from 2.8 to 2.0 seconds and memory to 620 MB, and the rankings on all 180 keyword test tasks came out identical.

Two bugs the benchmark found

  • Some Jev requests came back as HTTP 403 with an HTML page. The client reported "Jev rejected the API key", but the page was an edge firewall objecting to something in the source text. One such file cost its whole batch of six. Jev now reports it as rejected content, and the packer halves a rejected batch until only the offending file is lost.
  • The hook skipped "Stop writing to the SSE stream after the client aborts" as a conversational reply, because it starts with "stop". Only short prompts count as replies now.

What this doesn't show

  • File recall is not task success. This measures whether the right files come first, not whether an agent then makes the right change.
  • Commit subjects are short and sometimes cryptic. Requests to an agent are usually longer, which likely helps both keyword search and Jev.
  • No agent comparison was run for this release. The budget went to recall.

What it cost

Every Jev variant on both splits, the rejected sketcher included, billed 47.1 million input tokens: about $1.98. Responses are cached by request body, so re-running the published numbers costs nothing. The cache is attached to the release.
